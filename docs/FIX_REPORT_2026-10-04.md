# Исправления по анализу готовности — 4–5 октября 2026 года

Рабочая копия: `C:\ja3proxy\gocurl`, ветка `main`.
Этот документ дополняет исторический
[отчёт о готовности](READINESS_REPORT_2026-10-04.md), а не объявляет весь проект
завершённым. Коммит и push не выполнялись; предыдущие изменения сохранены.

## Исправлено

1. Импортированный целевой TLS-профиль больше не допускает PQ-эксперимент.
   Проверяется присутствие ключа эксперимента, а не непустое значение.
   Тесты охватывают `pq`, `pq:`, `pq:1`, `pq:0`.
2. CLI отклоняет HTTP/3 + PQ до сетевого обращения, как публичный Go API.
   CLI-тесты проверяют код 2, JSON-ошибку и отсутствие TCP/UDP-трафика.
   Отдельный API-тест проверяет отказ импортированного профиля + PQ до dial.
3. ConnectTimeout распространяется на целевое TLS/QUIC-рукопожатие,
   а не только на открытие сокета. Таймер не действует после успешного
   рукопожатия: медленный ответ не прерывается таймаутом подключения.
4. При неудачном целевом TLS-рукопожатии закрывается исходное соединение.
   Неудачные QUIC-подключения также освобождают принадлежащий dialer сокет;
   после успешного QUIC-подключения он закрывается при завершении соединения.
5. Отмена запроса и его более ранний deadline сохраняются через отделённый
   dial-контекст стандартного HTTP-транспорта Go. Отмена прерывает ожидающее
   целевое TLS-рукопожатие и закрывает сокет, а не только возвращает ошибку
   вызывающему API. Ошибка deadline не подменяется ошибкой закрытого сокета.
6. Контекст передаётся через DNS/ECH discovery, direct dial, `connect-to`,
   HTTP/HTTPS CONNECT и SOCKS5/SOCKS5H. Во время настройки прокси отмена
   закрывает открытые сокеты; после успеха отключается этот механизм
   отмены и снимаются временные дедлайны SOCKS-соединения.
7. Задержка между частями ClientHello прерывается при закрытии соединения,
   вместо ожидания всего заданного интервала. Неудачные SOCKS UDP setup
   освобождают как контрольный TCP-сокет, так и открытый UDP-сокет.
8. Plain DNS использует контекстный UDP/TCP exchange с закрытием сокета
   при отмене. Сохранён TCP fallback для усечённого UDP-ответа; новый
   локальный тест подтверждает обращение к обоим протоколам.
9. Импортированный uTLS больше не помещает nil-указатель в `net.Conn`.
   Удалены неиспользуемые приватные обёртки; преобразование ConnectionState
   не читает устаревшее поле uTLS. Проверка CLI-таймаута теперь проверяет
   `context.DeadlineExceeded` через цепочку ошибок вместо слова `timeout`.
10. Устранена локальная авария линтера: PATH выбирал Go 1.27.1, тогда как
    golangci-lint 2.10.1 собран с Go 1.26.6. Добавлен `scripts/check.ps1`,
    выбирающий установленный совместимый Go той же major/minor, что в go.mod,
    и восстанавливающий PATH, GOTOOLCHAIN и рабочую директорию после запуска.
    Проверен его выбор Go 1.26.6, остановка на настоящих замечаниях линтера
    и восстановление окружения. Скрипт не отключает проверки ради успеха.
11. Исправлена неполная проверка в PowerShell: `-bench=.` превращался
    в два аргумента `-bench=` и `.`, после чего запуск проверял только
    корневой пакет. В Windows-скрипте и CI аргумент заключён в кавычки.
    Аналогично исправлен `-coverprofile=coverage.txt` в CI: без кавычек
    PowerShell разделял его на `-coverprofile=coverage` и `.txt`.
    Разбиение воспроизведено диагностикой аргументов, а повторный полный
    тестовый запуск подтвердил все 15 пакетов, не только корневой.
12. Исправлены Markdown-списки и таблицы ТЗ; применены заданные форматтеры
    ко всему Go-коду проекта без vendor. `fmt --diff` больше не выдаёт правок.
13. WebSocket больше не превращает ошибку чтения заголовка кадра в EOF.
    CLI возвращает ошибки записи/чтения сообщения с исходной цепочкой причин:
    проверены усечённые заголовок и payload, masked server frame и timeout.
    При частичной записи сохраняется число принятых writer байтов.
14. CLI читает WebSocket через full-duplex `Response.Body`, сохраняя байты,
    которые HTTP-транспорт уже прочитал вместе с ответом 101. Новый тест
    отправляет upgrade и первый кадр одной записью; кадр не теряется.
    Старый `NewWebSocket(net.Conn, ...)` сохранён для совместимости.
15. Verbose-лог использует копию настоящего запроса вместо построения второго.
    WebSocket nonce в логе совпадает с отправленным серверу; file/stdin stream
    не читается для логирования. Replayable body копируется через `GetBody`.
16. HTTP/2 PRIORITY проверяет weight 1..256 до записи: значение 256
    кодируется как 255, а 0, 257 и 65535 отклоняются без сетевых байтов.
    Обработка SETTINGS, HEADERS/CONTINUATION и DATA разделена на функции
    с сохранением порядка кадров. Wire-тест проверяет каждый разрез входного
    потока, запись по одному байту, HPACK order, padding, PRIORITY и END_STREAM;
    чужой кадр или stream внутри CONTINUATION отклоняется.
17. GREASE определяется без сужающего преобразования. Все 65536 значения
    проверены на точное соответствие 16 GREASE-кодам и их нормализации.
    Алгоритмы JA3/JA4 не подменялись. Исключения MD5/SHA-1 относятся только
    к предусмотренному протоколами fingerprint/handshake-кодированию.
18. TLS-фикстуры больше не обрезают длины при приведении к uint16;
    границы 0/65535 и отказ для -1/65536 покрыты тестом. QUIC option bounds
    проверены на максимумах и первом переполнении до преобразования типов.
19. Исправлены все текущие замечания errcheck, revive, staticcheck,
    unconvert и unused; добавлены комментарии публичных profile-типов.
    `NewRequest` разделён на подготовку body и построение запроса, без
    изменения обработки бинарного файла и WebSocket data.
20. `requestArgs` вынесен в `pkg/gocurl/request_args.go` и разделён на builders

## Что остаётся

- Локальный lint и test gate зелёные; текущий проход устранил оставшиеся
  замечания runtime и тестов без отключения проверок. Это не заменяет
  запуск CI на чистом опубликованном checkout.
- Воспроизводимая поставка исходников и vendored патча из чистого коммита
  остаётся отдельным P0-пунктом. Неотслеживаемые файлы не добавлялись автоматически.
- Рабочий CLI/API путь DNS/proxy setup переведён на контекстный интерфейс.
  Совместимые legacy DialFunc/Dialer без DialContext остаются синхронным
  fallback; произвольный внешний legacy dialer немедленно прервать нельзя.
- Legacy зашифрованные DNS-upstream не предоставляют ExchangeContext.
  Адаптер немедленно возвращает отмену вызывающему коду, не закрывая общий
  upstream, но библиотечный worker может продолжить работу. Настройка
  Timeout=5 секунд не доказывает общий пятисекундный предел bootstrap,
  TLS и повторных попыток: DoT имеет отдельные внутренние дедлайны.
  Проверено завершение worker после освобождения тестовой fixture,
  не гарантируется немедленное прекращение любого зашифрованного обмена.
- Остальные API/CLI wire-сценарии, fuzz и документационные пункты backlog
  из первоначального отчёта сохраняются.
